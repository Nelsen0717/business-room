# 小二的模組庫

一招做法一份檔，是這門課的方法（六格、333、以終為始）做成的積木。每份寫著：什麼時候適合、為什麼有效、怎麼做、今天的事長這樣、兩週後怎麼判斷、紅線。小二照掌櫃的真實情況挑幾個組起來；用久了，每一間經營室都長成不一樣的樣子。

## 內建的 14 個（檔名就是編號）
- 找客：舊識問候 dormant-ties、聚點 hubs、名錄開發 directory、官網與商家頁 site-page、社群內容 social-post、付費廣告 paid-ads
- 迎客：一小時回覆 fast-reply、不用人工的流程 auto-flow｜成交：一次講完的報價 one-page-offer
- 口碑：評論邀請 review-ask、轉介紹 referral｜養客：自己的名單 own-list｜回客：叫回梯子 winback-ladder、新起點問候 fresh-start

## 完整做法在課程包

公開版只附這份說明和模組的名字、所屬的格；14 份完整的做法（為什麼有效、怎麼做、今天的事長這樣、兩週後怎麼判斷、紅線）在課程包裡，用課程碼換。

還沒換課程包的時候，小二認得每個模組的名字，照名字和「例行.md」的原則帶掌櫃做，並跟他說完整的做法在課程包。拿到課程碼之後，小二換成完整的那一份。

## 要上網找人、找地方的模組

名錄開發、聚點、社群內容、官網與商家頁、評論邀請，照上一層的「找客人的門路.md」：台灣的資料直接用瀏覽器看，查到的存進「我的經營室/資料/」。

## 小二怎麼挑、怎麼組
1. 先看最大的洞在哪一格、333 的起點在新客還是回頭客（名單少於 20 位，起點是新客）；至少一個模組補最大的洞。
2. 讀每份開頭的「適合」「不適合」，對照他說過的話和他的資料；對不上的不開。
3. 每個模組都要指回同一邊的一個目標，也指回他真實的來路或資料，寫成「為什麼開」。
4. 讓前後接得起來：名錄開發問到窗口，一次講完的報價接住；自己的名單整理好，叫回梯子才排得出人。
5. 訪談最後一次先開一到兩個：第一個補最大的洞；名單夠的話，第二個給回頭客；名單還不夠，第二個可以接著第一個做（例如問到窗口就寄菜單）。一次最多三個在跑（試做中加開著）；要開新的，先暫停或收工一個。
6. 新開的先試兩週。到判斷日照那份的「兩週後怎麼判斷」選一個：留下、加量、換做法、暫停，結果和數字記下來。
7. 盤點時看要不要長新的：先找內建的；都對不上、他又一再需要同一件事，才自己寫一份。

## 自己長的模組
寫在「我的經營室/模組/my-xxx.md」，編號用 my- 開頭（英數小寫和連字號，24 字內），格式跟內建一樣，更新課程包不會蓋掉。內建這一包只讀不改，想換做法就另寫一份。空白範本：

```
---
id: my-            # my- 開頭，例如 my-lunch-call
name:              # 10 字內
lane: new          # new 新客／return 回頭客／paid 付費／other 其他
node: 找客         # 找客、迎客、成交、口碑、養客、回客 選一
grows: list        # 存進哪一種：list 名單／site 官網與商家頁／search 被搜得到／flow 不用人工的流程（可省）
fits:              # 什麼情況適合（一句）
not_fit:           # 什麼情況不要用（一句）
lead: 這一期       # 每天做得到的量叫什麼，例如「這一期問候了幾位」
result:            # 算成果的是什麼，照地圖格式.md 的「怎麼算一位」
review_days: 14
---
## 為什麼有效（查得到的依據寫出處和限制；沒有就寫「實務經驗，沒有研究直接支撐」）
## 怎麼做（小二做的、掌櫃自己做的）
## 今天的事長這樣（一到兩個範例：什麼時候、在哪 → 做什麼 → 對誰，附草稿）
## 兩週後怎麼判斷（看哪個數字、多少算有效；門檻是設計選擇就明講）
## 紅線（法規與平台規定；送出規則見例行.md）
```
